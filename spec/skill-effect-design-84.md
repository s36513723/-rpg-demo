# Active 84技の効果初期案（2026-09-29）

315技カタログの Active 241件のうち、前回監査で個別の効果処理が空または効果方針を十分に表せないと判定された84件を対象とする。ID別の対象・発動条件・処理・暫定数値は [`skill-effect-design-84.js`](../skill-effect-design-84.js) に一件ずつ記載し、正本の `08_SkillDB` の AL:AP 列へ同期した。

この表は**設計データ**であり、戦闘エンジンはまだ読み込まない。従来の技の動作がこの設計通りになったという意味ではない。既存315技の技名、Mastery、Rank、SP案、Set Cost、旧セーブ移行状態は変更しない。すべての係数、成功率、持続、条件判定の詳細は**初期実装値・要レビュー**とし、実戦検証で調整する。

## 読み方

- `target`: 対象の選択規則。`ally_row` は同じ行の味方、`ally_adjacent` は隣接マス、`enemy_vertical` は同じ列の敵、`enemy_back` は後列の敵、`enemy_side` は側面隣列の敵。`self` は使用者。
- `condition`: 行動予約の条件。条件を満たさない技は選択前に理由を示し、SPを消費しない。`bonus_if_*` は技を選べなくする条件ではなく、該当時だけ加算する倍率（基礎倍率への加算）。元のSkill DBの `conditions` にある未行動・行動順・低HPは「使用制限」か「特効条件」か未確定なので、この解釈は要レビューとする。
- `trigger`: 反応技のみ。使用時には自分へ待機状態を予約し、指定の攻撃や押し引きを受けたとき一度だけ発動する。予約時にSPを支払い、発動しないまま当ラウンドが終わった場合も返さない。反応から反応を再帰発動しない。
- `operations`: `種別:値:持続ターン` の配列。`duration=0` は即時、`1` は次の関連判定または当ラウンド末まで、`2/3` はラウンド末に減算する持続効果。割合は `0.20=20%`。成功確率も同様。`damage` と `total_damage` はSkill DBの基礎 `power` と照合する予定値で、元のカタログ `mult` と二重適用しない。
- `runtime: design_only`: 実装と接続していない。`operation` 名を単に戦闘ログへ表示するだけで実装済みとみなさない。

## 実装時に共有する処理規則

1. 対象候補は行動予約時と発動直前に検証する。死亡・移動などで対象が消えた場合は既存の再対象ルールに従い、勝手に別陣営を対象にしない。
2. ダメージ、吸収、追加攻撃、撃破連鎖は命中→防御→HP変化→戦闘不能判定の順。`hp_drain` は実際に与えたHPダメージから回復する。
3. ガード、属性耐性、バリア、状態耐性、速度、命中、回避の重複上限と持続更新は共通の状態効果系で管理する。仮の上限は同種の最大効果を採用し、異種の軽減を乗算する。確定値ではない。
4. `reaction` 系は指定トリガーにつき一回、連鎖反応を発生させない。`cover` は対象の隣接関係が崩れた時点で解除する。
5. `formation_move`、`swap_position`、`advance`、`retreat` は空きマスと陣形ルールを守る。敵陣と味方陣を混ぜない。
6. 成功率、持続、対象規則、装備条件を含む個別処理の検証を終えるまで `implementation_ready` を「実装済み」へ変更しない。

## 数値と特殊処理の解釈

- `damage` は1回の基礎倍率、`bonus_if_*` は対応条件を満たしたときだけその倍率へ加算する。`priority` は行動順決定前に適用し、その後 `bonus_if_first_action` を判定する。条件を満たさない攻撃は基礎倍率で発動する。
- `multi_hit:3` と `total_damage:1.9` は、3回の命中判定で合計1.9倍相当（1回あたり1.9/3）。SPは1回だけ消費し、各命中後に戦闘不能を判定する。`second_hit` は同一行動の追加1回で、再帰追撃しない。
- `magic_guard` / `physical_guard` / `damage_guard` / `magic_barrier` は指定属性の被ダメージ割合軽減。`barrier_hp` は対象の最大HPに対する一時耐久割合。`cover` / `taunt` / `move_lock` / `leg_bind` は発生確率、`displacement_resist:1` は完全耐性。
- `hp_drain` は実際に減ったHPの割合を回復し、最大HPを超えない。`sp_restore` は即時SP、`sp_regen` は対象自身のラウンド末に固定SPを回復し、最大SPを超えない。
- `advance` / `retreat` / `side_step` / `formation_move` は使用者または選択味方を合法な空きマスへ動かす。`push_or_pull` は使用時に押す／引く方向を選ぶ。`swap_position` は対象と同じ陣営の合法な相手一体との交換に限定する。移動候補がなくても他の効果だけ実行する技では、移動部分だけを省略する。
- `weapon_magic_attribute` は術法属性の選択UIと適用元が未決定、`environment_attribute` は戦場テーマに対応する属性がない場合は無属性とする初期案。どちらも既存の属性相性を勝手に変更しない。
- `on_kill_followup` は撃破後、同じ列に残る最前の敵へ一回だけ追加攻撃する。`support_power` は次に付与する支援の割合部分を20%増加させ、持続は延長しない。`reveal_next_action` は確定している次の敵行動のみ表示する。

## 今回の検証で判明した未解決点

- 反応技、位置移動、属性付与、敵行動の予告、条件付き倍率を共通エンジンへ実装しない限り、84件の実戦効果は確認できない。
- `conditions` の「未行動」「行動順」「低HP」を技の使用制限とするか特効条件とするかは正本で詳細未定義。本案は技が無効化されにくい特効条件としているため、実装前に仕様確認が必要。対象は抜刀・居合・処刑斧・葬列。死線は低HP判定が使用者か攻撃対象かも未定義。
- 旧Skill DBの `target_rule` が効果方針と食い違う6件（剣閃、捨身斬、天崩、神速穿ち、重圧、地脈）は旧列を残し、新しい対象案との差を正本の整合メモに明示した。既存の対象仕様をランタイムで勝手に変更しない。
- 敵・味方の位置交換対象、導剣の属性の選び方、戦場テーマと自然術の属性対応、反応技のSP消費時点は初期案であり確定仕様ではない。

## 追加検証の優先順位

- 先にガード・バフ・デバフ・状態異常・位置移動・詠唱の共通処理を実装し、84 IDをその処理へ接続する。
- 条件付き技は未行動、先手、HP半分以下、空きマス、装備・投擲物の有無を境界値で検証する。
- 代表技だけでなく84件全てで、SP消費、対象、状態差分、持続終了、戦闘不能時の解除を実戦で確認する。旧296件からの個別移行表ができるまで、315件を戦闘デモへ一括置換しない。
